# Find_caches

Скрипт для случая, когда YouTube грузится «через раз»: старые видео играют, а новые
висят на бесконечной загрузке.

Программа находит пулы кэшей `googlevideo.com`, проверяет каждый узел и пишет готовые
строки для файла `hosts` в отдельный файл `hosts_suggest.txt`.

**Ничего не меняет в системе.** Только читает, проверяет и пишет один текстовый файл.

---

## Требования

**Python 3.7 или новее.** Внешние библиотеки не нужны, `pip install` не требуется —
только стандартная библиотека.

**Права администратора не нужны.** Они понадобятся только для правки `hosts`,
которую программа не делает.

**Доступ в сеть:**

| Куда | Порт | Зачем |
|---|---|---|
| `8.8.8.8` | UDP 53 | DNS напрямую, мимо файла `hosts` |
| `redirector.googlevideo.com` | TCP 80 | код пула |
| `www.youtube.com` и узлы кэшей | TCP 443 | имена пулов и проверка узлов |

**Что должно быть включено до запуска:**

- **zapret** — без него `youtube.com` не откроется вообще, и проверка узлов
  покажет всё мёртвым. Запускать **от имени администратора**: `winws.exe` без
  прав не стартует и пишет «requires elevation»;
- **QUIC в браузере выключен** (`chrome://flags/#enable-quic`) — иначе часть
  трафика идёт мимо правил и мимо hosts;
- **Secure DNS (DoH)** — на время запуска лучше выключить, см. ниже.

### Как проверить, что zapret работает

Проверяй в консоли:

```
curl -s -o NUL -w "%{http_code} %{time_total}\n" https://www.youtube.com/generate_204
```

`204` — работает. `000` — нет (соединение не установилось).

Если `curl` даёт `000` и на `https://www.google.com/generate_204` — дело не в
zapret, а в самом `curl` (в Windows 10 он иногда падает с
`schannel: AcquireCredentialsHandle failed: SEC_E_NO_CREDENTIALS`). Тогда просто
открой `https://www.youtube.com/` целиком: главная с видео открылась — работает.

## Запуск

Двойной клик по `find_caches.bat` — он сам найдёт Python и оставит окно открытым.

Или вручную:

```
python find_caches.py
```

Если несколько версий Python:

```
py -3.11 find_caches.py
```

### Если имя пула видно только в DevTools

Бывает, что в F12 → Network видно имя пула (например `sn-q4fzen7r`), но в DNS-кэш
и историю оно не попало — поток не догрузился, запрос отменился. Тогда имя можно
задать вручную:

```
python find_caches.py sn-q4fzen7r
```

Принимает любую форму: `sn-q4fzen7r`, `rr4---sn-q4fzen7r.googlevideo.com`,
целиком URL из DevTools. Можно несколько через пробел.

Или создай рядом с программой файл `pools.txt` и впиши имена туда, по одному
в строку — тогда программа будет брать их оттуда при каждом запуске, без аргументов.

Если такого пула нет в DNS (все восемь узлов `НЕТ`), программа так и напишет.
Обычно это рекламные потоки — правки в `hosts` не нужны, на видео они не влияют.

## Что делает

1. **Имена пулов со страниц YouTube** — параметр `mn=` в ссылках на видео.
   Может не сработать, если YouTube покажет проверку на робота — см. ниже.
2. **DNS-кэш Windows** — `ipconfig /displaydns`.
3. **История браузеров** — Vivaldi, Chrome, Edge, Opera, Opera GX, Brave, Yandex,
   Firefox и форки (Waterfox, LibreWolf).
4. **`report_mapping`** — код пула вида `vimpelcom-ovb1`.
5. **Имена, заданные вручную** — аргументом или файлом `pools.txt`.

### Какие браузеры читаются

Программа смотрит все браузеры, которые найдёт.
Ничего указывать не нужно, ищет сама.

**На Chromium** (Vivaldi, Chrome, Edge, Opera, Brave, Yandex): файл `History`,
таблица `urls`, колонка `url`.

**Firefox и форки**: файл `places.sqlite`, таблица `moz_places`, колонка `url`.

Профиль берётся целиком — `Default`, `Profile 1`, `Profile 2` и так далее.
Копия базы делается во временный файл, поэтому открытый браузер не мешает
и ничего не блокируется.

В выводе видно, из какого браузера сколько записей пришло:

```
[3/4] История браузеров (работает и при DoH)
   Firefox      4 записей
   sn-8ph2xajvh-v8ce            встречалось 3 раз
   sn-ug5onuxaxjvh-n8v6         встречалось 1 раз
```

Если браузера нет в списке (например, он portable или профиль в нестандартном
месте) — его история просто не попадёт в счёт. Тогда имена всё равно найдутся
через источники 1, 2 и 4.

Дальше проверяет каждый узел: **TCP + TLS + реальный HTTP-ответ**. Узел считается
живым только если TLS прошёл И пришёл HTTP-статус. Это отсекает случай
«пул жив, а видео не работает».

Результат — файл `hosts_suggest.txt`, в нём только строки `IP имя`, без комментариев.

## Про DoH и почему источников четыре

Когда в браузере включён Secure DNS, браузер ходит за адресами напрямую в
`dns.google` или `cloudflare-dns.com` и **не пишет имена в DNS-кэш Windows**.
Второй источник из-за этого пустеет.

Поэтому источников четыре:

- **1, 3, 4 работают при любом DoH** — там сами URL и прямой DNS, а не кэш Windows;
- **2 (DNS-кэш Windows)** — только при выключенном DoH.

Если хотите, чтобы работал и второй: на время выключите Secure DNS в браузере,
откройте видео, запустите программу. Потом DoH можно вернуть.

**Важно:** Secure DNS включайте **после** того, как вставили строки в `hosts`.
Если включить раньше, браузер может закэшировать старые IP и правка не подействует.

Если Secure DNS не стартует, можно закрепить адреса DoH-серверов в `hosts`
(по желанию, из обсуждения #16448):

```
1.1.1.1 one.one.one.one
2606:4700:4700::1111 one.one.one.one
8.8.4.4 dns.google
2001:4860:4860::8844 dns.google
146.112.41.2 doh.opendns.com
2620:119:fc::2 doh.opendns.com
```

## Что делать с результатом

1. Открыть `C:\Windows\System32\drivers\etc\hosts` Блокнотом **от имени администратора**.
2. Удалить оттуда все старые строки с `googlevideo` (особенно с `0.0.0.0`).
3. Вставить содержимое `hosts_suggest.txt`.
4. Сохранить и выполнить `ipconfig /flushdns`.
5. Полностью закрыть браузер и открыть заново.

Пересчитывать строки нужно после смены сети и когда видео снова начнёт падать
«через раз»: узел, живой сегодня, завтра может быть мёртвым, и наоборот.

---

## Почему это работает

YouTube отдаёт видео не с одного сервера, а с пула кэшей
`rr1..rr8---sn-XXXXXXXX.googlevideo.com`. Часть узлов блокируется по IP на 443
порту (при этом по 80 порту сервер отвечает нормально), а правила zapret завязаны
на домен и такие узлы обойти не могут.

Поэтому нужно не блокировать кэши через `0.0.0.0` — это убивает и живые узлы, —
а перенаправить мёртвые имена на живые IP того же пула.

## Если YouTube показал проверку на робота

Шаг 1 (имена пулов из `mn=`) может не сработать: YouTube отдаёт `302` на
`google.com/sorry`, если запрос пришёл не из браузера. Программа это распознаёт
и пишет об этом. Источники 2, 3 и 4 от этого не зависят — имена всё равно найдутся.

Если хотите, чтобы работал и первый: откройте любое видео в браузере, пройдите
проверку, потом запустите программу снова.
