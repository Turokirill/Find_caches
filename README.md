# Find_caches

Скрипт для обхода проблемы, когда YouTube грузится «через раз»: старые видео играют, а новые —
бесконечная загрузка.

Программа находит пулы кэшей `googlevideo.com`, проверяет каждый узел (TCP + TLS, 3 попытки)
и печатает готовые строки для файла `hosts`.

**Ничего не меняет.** Только читает и печатает — `hosts` правится руками.

---

## Требования

**Python 3.7 или новее.** Внешние библиотеки не нужны, `pip install` не требуется —
используется только стандартная библиотека (`socket`, `ssl`, `struct`, `subprocess`, `re`,
`concurrent.futures`).

**Права администратора не нужны.** Они понадобятся только для правки `hosts`, которую
программа не делает.

**Доступ в сеть:**

| Куда | Порт | Зачем |
|---|---|---|
| `8.8.8.8` | UDP 53 | DNS напрямую, мимо файла `hosts` |
| `redirector.googlevideo.com` | TCP 80 | определить код пула |
| `www.youtube.com` и узлы кэшей | TCP 443 | имена пулов и проверка узлов |

Если zapret выключен, `https://www.youtube.com` не откроется — шаг 1 (имена пулов из `mn=`)
пропустится, но шаги 2 и 3 отработают и всё равно дадут результат.

---

## Запуск

**Двойным кликом по `find_caches.bat`** — он сам найдёт Python (`python` → `py` → стандартные
пути), запустит скрипт и оставит окно открытым.

**Или вручную:**

```
python find_caches.py
```

Если установлено несколько версий Python:

```
py -3.11 find_caches.py
```

---

## Что делает

1. **Имена пулов со страниц YouTube** — достаёт параметр `mn=` из ссылок на видео.
2. **Имена из DNS-кэша Windows** — `ipconfig /displaydns`, то есть куда браузер уже ходил.
3. **Код пула через `report_mapping`** — например `vimpelcom-ovb1`, тогда узлы называются
   `rr1.vimpelcom-ovb1.googlevideo.com` … `rr8.`.
4. **Проверка узлов** — каждый узел по 3 попытки TCP + TLS, вердикт «жив» или «мёртв»,
   и готовые строки для `hosts`.

---

## Что делать с результатом

1. Открыть `C:\Windows\System32\drivers\etc\hosts` Блокнотом **от имени администратора**.
2. Удалить оттуда все старые строки с `googlevideo` (особенно с `0.0.0.0`).
3. Вставить строки из блока «строки для hosts» — сначала IP, потом имя.
4. Сохранить, затем выполнить `ipconfig /flushdns`.
5. Полностью закрыть браузер и открыть заново.

Строки надо пересчитывать после смены сети и когда видео снова начнёт падать «через раз»:
узел, живой сегодня, завтра может быть мёртвым, и наоборот.

---

## Почему это работает

YouTube отдаёт видео не с одного сервера, а с пула кэшей `rr1..rr8---sn-XXXXXXXX.googlevideo.com`.
Часть узлов блокируется по IP на 443 порту (при этом по 80 порту сервер отвечает нормально),
а правила zapret завязаны на домен и такие узлы обойти не могут.

Поэтому надо не блокировать кэши через `0.0.0.0` — это убивает и живые узлы тоже, — а
перенаправить мёртвые имена на живые IP того же пула.
